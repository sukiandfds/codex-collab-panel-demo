# 项目群聊与多 Agent 讨论

## 用户原话

> 没想好。初步想的是：1.群里有其他真人在线时，用@调用助手。2.群聊只有一个真人在线时，1.小助手负责分配给对应的人来进行回复。2.默认项目经理回复。项目经理分发任务后，各个助手要给出进度。然后可以针对特定对话继续进行对话。。先记下来，推送一下吧。之后再说

## 助手初步理解

群聊需要根据真人在线情况采用不同的 Agent 交互方式：多人在线时，用户通过 `@` 明确调用助手；只有一名真人在线时，由整理和分派型小助手负责理解消息并路由给对应角色，未明确指定时默认由项目经理 Agent 回复。项目经理完成分派后，各执行 Agent 需要公开报告进度；用户可以围绕某一条 Agent 对话继续追问，而不必重新描述任务。

## 简短摘要

提供项目群聊、多个 Agent 参与、可见的分派进度和针对特定对话的连续追问。

## 具体内容

使用场景：用户与其他真人和多个 Agent 在同一个项目群中讨论、分工和追踪结果。多人在线时，用户用 `@` 调用指定助手；只有一个真人在线时，小助手负责整理消息并分配给对应角色；没有明确指定时，默认由项目经理 Agent 回复。项目经理分发任务后，各 Agent 在群内持续提供进度，用户可以针对某条对话继续沟通。

当前体验：已有真实群聊、四个 Agent、讨论模式、@、附件和增量回复；上述“按在线人数路由、默认项目经理、分派后进度和特定对话连续追问”仍属于需求梳理阶段。

交互变化：在基础消息、过程、断线恢复、停止、追加和失败反馈可靠的前提下，增加多人在线时的明确 `@` 调用、单人在线时的小助手分派、项目经理默认接待、Agent 进度反馈和对话级连续追问。

## 预计效果

用户可以自然地在群里提问，不必记住所有 Agent 的分工；多人在线时可以明确点名，单人在线时由小助手协助分派。用户能看懂谁正在处理、任务进展到哪一步，并能围绕特定对话继续沟通，不会因为群聊形式掩盖基础能力问题。
