# 07 测试、构建与文档

## 当前验证能力

| 类型 | 当前入口 | 覆盖情况 | 缺口 |
| --- | --- | --- | --- |
| Node 服务端测试 | `windows/tests/*.test.mjs` | 路由、store、执行、群聊、多 Agent、Artifact 等覆盖较多 | 边界组合和跨服务真实链路仍少 |
| 前端类型检查 | `web-ui/package.json` 的 `tsc -b` | 可通过生产构建执行 | 没有独立 CI 门禁，分支上的前端错误可能不被自动发现 |
| 前端生产构建 | 根 `pnpm build:ui` | 本地开发记录经常使用 | `.github/workflows/ci.yml` 未直接执行 `pnpm build:ui` |
| 浏览器交互 | 外部 Playwright/临时测试记录 | 部分功能有截图或实机记录 | 没有与源码变更绑定的稳定浏览器 smoke suite |
| PowerShell/Node 语法 | CI 和 `windows/tests/run-tests.ps1` | 有语法和平台检查 | 不能证明 UI 交互、SSE 重连和跨入口一致性 |
| 真实服务验收 | 手动启动 `9360` | 依功能历史记录存在 | 不属于统一 CI，容易出现“测试绿但页面未验收” |

| 场景 | 当前状态 | 应补的证据 |
| --- | --- | --- |
| 按日期读取，当天消息少于 limit 且下一天有消息 | 未覆盖 | store 单元测试，必须保证只返回目标日期 |
| 同一 Agent 在一条回复中重复提及 | 未覆盖 | `newMentionedAgentIds` 测试，结果按 Agent ID 去重 |
| 群聊能力菜单点击和键盘导航 | 未覆盖 | 浏览器组件 smoke test |
| 员工群聊投影超过 300 条 | 未覆盖 | 历史分页集成测试 |
| 群聊队列重启恢复 | 当前功能明确为进行中 | 持久化 Job/Run 测试和受控重启验收 |
| 单人/群聊内容渲染一致 | 未覆盖 | 同一组 Markdown、图片、附件和 Artifact 的双入口截图或 DOM 断言 |
| 多业务项目切换后侧栏和房间同步 | 主要是手动验收 | 项目目录、房间、URL 和 SSE 的跨页面测试 |

## 文档漂移

| 文档 | 当前问题 | 影响 |
| --- | --- | --- |
| `FEAT-002-group-multi-agent.md` | 部分章节仍把消息样式、历史和流式列为后续开发，但当前提交已经加入相关代码 | 维护者无法从文档判断哪些是已实现、哪些只是未验收 |
| `docs/architecture/` | 架构文档的代码基线早于当前员工/群聊扩展 | 新代码中的跨域例外没有及时登记 |
| `PROJECT.md` | 项目说明更新日期早于当前审查提交 | 系统级入口和现状需要在审查结束后同步 |
| 历史开发日志 | 验证结果散落在功能文档、项目管理和 records | 同一功能的“已完成”和“待验收”容易被重复解读 |

## 建议的统一门禁

| 门禁 | 目的 | 触发时机 |
| --- | --- | --- |
| `node --check` | 后端语法 | 每次服务端变更 |
| `node --test windows/tests/*.test.mjs` | 服务端回归 | 每次后端或接口变更 |
| `pnpm build:ui` | 前端类型和生产构建 | 每次前端变更，建议加入 CI |
| `git diff --check` | 空白和补丁质量 | 每次提交 |
| 最小浏览器 smoke | 页面入口、发送、菜单、重连和关键导航 | 触及 UI、实时或路由时 |
| 真实服务验收 | app-server、cwd、权限、跨项目和长任务 | 发布或核心运行时变更 |

测试通过只能证明对应测试覆盖的契约，没有覆盖的边界必须在文档中明确标记为“未验证”。
