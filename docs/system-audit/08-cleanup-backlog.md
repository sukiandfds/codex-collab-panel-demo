# 08 系统清理待办

本表按“先统一语义，再减少重复，最后物理拆分”的顺序排列。没有用户明确授权前，不执行删除、移动或大规模重构。

## 优先级表

| 优先级 | 清理目标 | 当前问题 | 最小可行动作 | 完成证据 |
| --- | --- | --- | --- | --- |
| P0 | 建立唯一的项目/员工/房间身份解析 | 前端、员工注册表、项目身份、房间快照各自拼装 | 定义 `ProjectIdentity`、`AgentIdentity`、`RoomBinding` 的读取接口，先不移动文件 | 所有入口只通过接口取得名称、root、roomId、成员和能力 |
| P0 | 统一角色策略 | `manager`、`developer` 等 ID 分散在前端和多个后端服务 | 建立系统策略：默认接待、代码交付、审查、汇总由配置解析 | 修改员工 ID 或名称时不需要改页面和路由源码 |
| P1 | 修复群聊能力菜单 | 父容器禁用 pointer events，且能力只插入文本 | 恢复菜单交互；明确“插入指令”或“执行能力”的产品语义 | 鼠标、键盘、Escape、点击外部和发送链路有测试 |
| P1 | 修复日期历史边界 | 按日期分页可能混入下一天 | `getMessagePage` 对日期页计算明确的 `[start,end)` 范围 | 日期测试覆盖单条、跨天、limit 和不存在日期 |
| P1 | 修复重复 Agent 交接 | 新提及列表按位置返回，未按 Agent ID 去重 | 在交接入口按 Agent ID 去重，保留首次出现顺序 | 同一 Agent 重复提及时只执行一次 |
| P1 | 统一员工群聊历史读取 | 员工项目读取 snapshot 最近 300 条，主群聊读取分页历史 | 员工投影使用统一历史接口，并明确只读投影字段 | 300 条以上历史在两个入口的范围和游标一致 |
| P1 | 给群聊任务建立可恢复账本 | `workQueue/currentRun` 在内存 | 新增 `DiscussionJob/AgentRun/ActivityEvent` store，当前执行器作为消费者 | 重启后 queued/running/failed 状态可恢复或明确中断 |
| P1 | 统一消息和活动视图 | `SessionMessage`、`GroupMessage`、员工消息无法共用渲染和历史 | 增加 `MessageView/ActivityView/HistoryPage/SendReceipt` 转换层 | 单人、群聊、员工投影可使用同一组内容和状态展示组件 |
| P2 | 收敛内容渲染 | 单人 `ContentRenderer` 和群聊 `ReactMarkdown` 分裂 | 以 `ContentBlock` 为基线，群聊只提供消息外壳 | 同一 Markdown、媒体、附件和 Artifact 在两入口一致 |
| P2 | 统一原子写入和关闭协议 | 多个 store 复制临时文件、rename、writeQueue、close | 提取无业务含义的 `atomic-json-store` 和 `flushable` 接口 | 新 store 不再复制持久化模板，关闭顺序可检查 |
| P2 | 拆核心超长文件 | 组件和 Hook 同时管理数据、状态、视图、实时和动作 | 先写调用方和导出契约，再按职责拆，不改变外部 API | 单元测试、构建和真实 UI 行为不变 |
| P2 | CI 增加前端门禁 | 当前 CI 没有统一执行 UI 生产构建 | 在 CI 增加 `pnpm build:ui` 和最小前端检查 | 前端提交在 CI 中能阻止构建回归 |
| P2 | 建立浏览器 smoke 目录 | 交互 bug 只能靠手动发现 | 固定入口、视口、发送、菜单、侧栏、重连和历史场景 | UI 关键路径有可重复运行证据 |
| P3 | 同步功能状态文档 | 代码、功能状态、架构基线日期不一致 | 每个系统级改动同步状态、证据和未验收项 | 文档可准确回答“已实现/已构建/已运行/已验收” |

## 不应作为本轮清理目标的内容

| 内容 | 原因 |
| --- | --- |
| `runtime/` 活跃数据 | 属于用户状态，删除会造成历史、上传或员工记录丢失 |
| `macos/` 和 Windows Dream Skin | 是历史产品线，不应因 Web 业务整理被误删 |
| 现有四个 Web 入口 | 入口收敛是产品决策，不是架构清理的自动结果 |
| 员工独立项目目录 | 它是系统内置员工的身份边界，不是重复项目，应保留并统一接口 |
| 所有群聊员工子会话 | 记录本身有价值，应先定义投影语义再决定是否展示或归档 |

## 建议执行顺序

1. 先完成 P0 身份和角色策略表，不改 UI。
2. 处理 P1 的四个已确认问题和群聊任务账本。
3. 以统一视图接口对齐单人、群聊和员工投影。
4. 再拆超长文件和重复持久化模板。
5. 最后补 CI、浏览器 smoke 和文档状态同步。
