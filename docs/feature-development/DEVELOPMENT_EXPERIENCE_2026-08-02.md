# 2026-08-02 开发经验与问题复盘

## 1. 今日工作范围

今天围绕两个用户可见问题进行维护：

1. iPhone 上点击 Codex 输入框后页面自动放大、顶部系统区域遮挡内容、键盘出现后页面显示不完整。
2. 项目管理页面加载和页面切换的体感速度明显慢于 Codex 页面切换对话。

本日没有修改 Codex 执行协议、消息解析、群聊业务逻辑或公网入口，也没有启动、重启、提交或推送服务。

## 2. 结论先行

- iPhone 的主要问题不是没有任何移动端样式，而是缺少 iOS 专项约束：表单字体小于 `16px` 会触发 Safari 自动缩放；`viewport-fit=cover` 需要配合安全区；固定/绝对定位输入区需要配合动态视口。
- 项目管理接口不是主要瓶颈。本机测得 `/api/project-management` 约 `95ms`，而 Codex 会话列表约 `162ms`。真正影响体感的是整页导航、Service Worker 的网络优先导航策略，以及项目页在缓存内容可用时仍然先显示空白加载态。
- 最小有效修复是：移动端通用视口和安全区适配；页面导航缓存优先、后台更新；项目管理摘要先使用缓存渲染，再静默请求最新数据。没有立即重写成统一 SPA，也没有扩展后端任务系统。

## 3. 问题记录

### EXP-001：iPhone 输入框聚焦后页面自动放大

- 用户现象：点击输入框后页面比例变大，底部设置和右侧内容被截断，页面无法完整阅读。
- 代码证据：单人 Codex 文本框原来使用 `14px`；群聊文本框使用 `13px`；模型、上下文和其他下拉控件也使用更小字号。
- 根因：iOS Safari 对聚焦时字体小于 `16px` 的表单控件会自动放大页面。放大后，CSS 视口仍按原布局计算，但实际可视宽度变窄，于是产生“横向被截断”的连锁现象。
- 错误判断：不能把右侧控件被截断直接归因于设置栏宽度不足，也不能先大幅重排底部布局；必须先排除浏览器自动缩放。
- 处理方式：触摸设备上的 `input`、`textarea` 和 `select` 统一保证 `16px`；增加 `-webkit-text-size-adjust: 100%`；为输入容器增加 `min-width: 0`。
- 用户预期变化：点击输入框后页面保持原比例，模型、上下文和发送控件不再因为 Safari 放大而跑出屏幕。
- 状态：已实现，等待真实 iPhone/iPad 体验确认。

### EXP-002：Dynamic Island/刘海区域遮挡页面

- 用户现象：页面顶部出现黑色系统横条，部分页面内容看起来被盖住。
- 根因：页面使用 `viewport-fit=cover`，允许内容铺到系统安全区；原布局没有统一预留 `safe-area-inset-top`。截图中的黑色横条属于 iPhone 系统区域，不是网页自己绘制的组件，网页不能直接隐藏它。
- 错误判断：不能通过修改网页颜色、层级或删除一个普通横幅来“消除”系统横条；正确做法是把内容移出系统安全区。
- 处理方式：根节点增加顶部安全区；移动侧栏、页面切换入口和更新提示使用安全区偏移；侧栏底部同时保留底部安全区。
- 用户预期变化：顶部标题、切换入口和页面正文不再进入 Dynamic Island/刘海区域。
- 状态：已实现，等待真实设备确认不同机型的安全区数值。

### EXP-003：键盘弹出后输入区和正文可视范围不稳定

- 用户现象：键盘弹出后，页面底部内容可能被覆盖，输入区与可视区域关系不稳定。
- 根因：页面根节点原来只使用 `height: 100%`，输入区在主区域中使用绝对定位；`body` 和主区域还设置了 `overflow: hidden`，没有使用动态视口高度。
- 处理方式：支持 `100dvh`，让根节点和页面壳随浏览器可视高度变化；底部输入区继续使用已有 `safe-area-inset-bottom`，没有加入复杂的高频 `visualViewport` 轮询。
- 设计边界：先使用浏览器标准动态视口解决普遍问题；只有真实设备仍出现键盘覆盖时，才针对具体 Safari 版本增加最小事件处理，不能预先引入常驻监听。
- 用户预期变化：键盘打开时，输入框和发送区域跟随可视区域，正文不会因为固定高度继续占用被键盘遮挡的空间。
- 状态：已实现，等待真实设备确认。

### EXP-004：项目管理页面加载慢，但接口本身并不慢

- 用户现象：从 Codex 页面切换到项目管理页面时，需要等待，体感明显慢于 Codex 页面内切换对话。
- 现场测量：本机项目管理接口返回 `200`，约 `95ms`；会话列表接口返回 `200`，约 `162ms`。
- 根因：项目管理和 Codex/群聊是多个 HTML 入口，切换时会整页导航。原 Service Worker 对导航采用“先请求网络，失败才使用缓存”，公网链路延迟直接变成用户等待时间。项目管理页请求尚未完成时，界面也只显示空白加载状态。
- 错误判断：不能看到“加载慢”就立即重写 Markdown 解析器、引入数据库或统一 SPA；必须先区分接口耗时、页面导航耗时、资源缓存命中和首屏渲染等待。
- 处理方式：
  - Service Worker 对已缓存页面采用“缓存优先、后台重新验证”；首次没有缓存时才等待网络。
  - 项目管理摘要从 `sessionStorage` 读取旧值后立即渲染，网络请求在后台更新。
  - 保留 API 的 `no-store`，避免把真实项目数据错误地长期固化在 HTTP 缓存中。
- 用户预期变化：再次进入项目管理页时，先看到上一次的项目摘要，最新内容返回后自动替换；网络较慢时不再出现整页空白等待。
- 状态：已实现，等待用户实际切换体验确认。

### EXP-005：Windows 端口检查工具不可用，但服务实际正常

- 用户现象：`Get-NetTCPConnection` 报 CIM/WMI 无法连接，命令结果容易被误读为 `9360` 没有监听。
- 同日证据：该查询失败后，直接请求本地 `/api/project-management?token=demo123` 仍返回 `200`。
- 根因：本机 WMI/CIM 服务不可用；“查询失败”和“没有监听”不能使用同一个结果表示。
- 正确路径：Windows 端口优先使用 `netstat.exe -ano -p tcp` 找 PID，再使用真实 HTTP 健康接口确认服务是否可用。不能因为 CIM 命令失败就重启或重复启动服务。
- 状态：已有 `PROC-002`，今天再次确认该规则仍然有效；本次没有执行重启。

### EXP-006：构建通过不等于真实设备体验已通过

- 今日验证：`pnpm build:ui`、`node --check web-ui/public/sw.js` 和 `git diff --check` 均通过。
- 未验证：真实 iPhone/iPad 键盘行为、Dynamic Island 安全区、Service Worker 已激活后的实际切换时间。
- 经验：构建只能证明 TypeScript/CSS/打包没有明显错误，不能证明公网、Service Worker、浏览器缓存或实体设备的用户体验。
- 当前边界：本轮按“快速、轻量、不启动或重启服务”的范围完成代码级验证；实体设备体验由用户实际验收，不能把构建结果写成“所有设备已验证”。

### EXP-007：已有未提交改动较多，必须避免误覆盖

- 现场状态：工作区同时存在功能文档、项目管理新目录、前端组件、后端路由和测试的未提交改动。
- 正确路径：修改前先执行 `git status --short`；只在本次问题所属文件中做小补丁；不使用 `git reset --hard`、`git checkout --` 或清理命令；结束时再次确认差异范围。
- 本次结果：移动端修复只涉及通用样式和移动布局；性能修复只涉及 Service Worker、项目管理缓存读取和首屏状态；没有回滚或覆盖其他未提交内容。

## 4. 今天出现的低效率点

### 4.1 第一次技能路径判断错误

曾按错误的本地路径读取前端调试技能，随后根据当前技能目录映射改用正确路径。经验是：使用技能前先确认实际安装路径，不要凭目录名猜测。

### 4.2 初次文本搜索范围过大

第一次用 `rg` 同时扫描大量文档、源代码和目录，输出被截断，降低了定位效率。经验是先列出目标目录，再只搜索组件、入口和相关关键词；不要把整个仓库当作一次性上下文。

### 4.3 先验证用户路径，再决定是否扩展架构

项目管理页速度问题如果只看后端，会误以为需要重写存储层；实际测量后发现本地接口很快，修复重点应放在导航缓存和首屏状态。以后遇到“页面慢”，固定拆成：

```text
接口耗时 -> 页面导航耗时 -> 静态资源缓存 -> 首屏渲染等待 -> 用户可见反馈
```

## 5. 可复用的防再犯规则

1. 移动端表单控件先检查 iOS `16px` 自动缩放，再讨论布局重排。
2. 使用 `viewport-fit=cover` 时，必须同时检查顶部和底部安全区；系统横条不能通过网页层级隐藏。
3. 键盘适配优先使用 `100dvh` 和已有安全区；没有真实设备证据时，不增加常驻 `visualViewport` 监听。
4. 页面速度先做分层计时，不把公网延迟、接口解析、静态资源和 React 首屏混成一个“后端慢”。
5. 有缓存内容时优先显示旧内容并后台更新，除非数据具有强一致性要求；项目管理摘要允许短时间 stale-while-revalidate。
6. Service Worker 导航策略必须和更新策略一起设计：缓存优先提升切换速度，版本接口和更新提示负责发现新版本。
7. `pnpm build:ui` 和 `git diff --check` 是基础门，不是实体设备或公网体验验收。
8. 服务状态检查使用 `netstat + HTTP` 双重证据，不把 WMI/CIM 查询失败解释成端口未监听。
9. 发现多个未提交改动时，先保护工作区，再按功能边界修改；不借机整理无关代码。
10. 用户只要求性能和体验修复时，不顺带重写 SPA、数据库、任务系统或公网架构。

## 6. 后续只保留两个验证点

1. 用 iPhone 实测：点击输入框是否不再放大，键盘打开后输入区是否可见，顶部内容是否避开 Dynamic Island。
2. 在同一浏览器中往返切换 Codex、群聊和项目管理页：确认缓存页面立即出现，后台更新不会闪烁或回退旧内容。

如果这两个验证点仍失败，再根据具体设备和时间点补最小修复，不先扩大架构范围。
