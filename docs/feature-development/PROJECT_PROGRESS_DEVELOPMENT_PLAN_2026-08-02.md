# 项目进度面板开发计划

## 1. 本轮目标

把当前直接渲染 `FEATURE_INDEX.md` 的进度页，升级为面向用户快速判断的项目面板：

- 用户打开页面后，先看到当前计划、当前进行中的工作和最近更新。
- 每个条目保留需求来源、助手初步理解、用户体验变化、关联关系、状态和更新时间。
- 日志展示“什么时候发生了什么变化”，完整内容进入条目详情，不把页面变成长文档。
- 数据继续来自仓库现有功能索引和 `FEAT-*.md`，不创建独立任务系统，不伪造 Agent 运行状态。

## 2. 行业标准依据

本轮字段和展示参考 Jira、Linear、Asana、OpenProject 的共同模式，并结合本项目已有调研：

- 工作项需要稳定编号、类型、状态、优先级/影响级别、负责人或来源和更新时间。
- 项目更新应是带时间的快照，记录本次变化，不覆盖历史更新。
- 当前摘要和完整详情分层展示；列表用于扫描，详情用于理解和追溯。
- 关联项需要可定位，至少支持来源、依赖、阻塞和相关功能等关系。
- AI Agent 项目必须区分工作项更新时间、真实执行时间和心跳时间；本轮不把页面更新时间当成 Agent 正在运行的证据。

## 3. 每个条目的统一内容

### 3.1 列表摘要

列表只显示以下信息，保证用户可以快速扫描：

- 条目编号与类型：例如 `FEAT-001`、`BUG-012`。
- 简短摘要：一句话说明条目解决什么问题。
- 级别：Bug/事故显示影响级别，普通工作项显示优先级；统一使用 `P0` 至 `P3` 标签。
- 当前状态：待处理、进行中、等待确认、阻塞、已完成、已取消等。
- 更新时间：固定的日期时间和本次更新摘要。

### 3.2 条目详情

点击列表条目后打开详情。桌面端使用右侧详情面板，移动端使用全屏详情页。

详情顺序固定为：

1. 用户原话：保留原始表达，不改写为技术结论。
2. 助手初步理解：只解释用户字面意思、明确目标和未明确点，不分析相关文件。
3. 具体内容：使用场景、当前体验、交互变化、要解决的问题。
4. 预计效果：使用场景、修改后体验、用户看到或可以操作什么、完成判定。
5. 关联条目：来源、依赖、阻塞、相关功能等可定位关系。
6. 文件与证据：功能文档、提交、对话或验证记录。
7. 更新历史：按时间倒序显示每次实际变化。

功能文档没有保留原始用户原话时，必须明确显示“当前功能文档未记录原始用户原话”，不能把助手改写内容冒充原话。

## 4. 页面展示规划

### 4.1 顶部区域

```text
项目概览
今日计划
当前进行中
最近更新
```

“今日计划”只使用功能索引中明确写入的待办，不根据截止时间自动猜测。系统推断内容不能直接冒充计划。

“当前进行中”只显示真实记录为 `in_progress` 的条目；页面更新时间、心跳或 tracker 更新时间不能单独证明任务正在运行。

### 4.2 分类区域

顶部之后按分类折叠展示：

- 调研任务
- 开发任务
- Bug 与维护
- 产品决策
- 验证与交付
- 项目资料与历史记录

分类默认收敛，用户点击分类后查看其中的条目。主列表不展开完整技术内容。

### 4.3 日志区域

日志面板使用紧凑列表，不使用大量默认展开的折叠卡片。每条日志显示：

```text
时间 · 条目编号 · 状态变化
本次更新内容
用户影响
```

点击日志进入对应条目详情；完整历史在条目详情中按时间线查看。日志是追加记录，不覆盖旧版本。

## 5. 本轮实施范围

### M1：本轮必须完成

- 服务端读取现有 `FEATURE_INDEX.md` 和对应 `FEAT-*.md`。
- 输出结构化项目概览、计划、进行中条目、分类条目和更新日志。
- 前端实现摘要列表、分类折叠、条目详情和日志列表。
- 详情展示用户原话、助手初步理解、具体内容、预计效果、关联条目和证据入口。
- 桌面端详情面板与移动端全屏详情兼容。
- 保留当前项目 UI 令牌和基础导航，不改基础 UI 样式。

### M1 不做

- 不开发 Jira/Asana 类编辑器、任务创建、拖拽看板或 Gantt。
- 不建立独立数据库或新的通用任务系统。
- 不伪造 Agent 实时运行状态，不把文档更新时间当成执行状态。
- 不扩展多项目、权限、预算、工时和组织管理。
- 不修改 Codex 对话页、群聊页或公网入口。

## 6. 数据边界

```text
FEATURE_INDEX.md + FEAT-*.md
    -> project-progress-store
    -> /api/project-progress
    -> ProjectProgressApp
        -> 摘要列表
        -> 条目详情
        -> 更新日志
```

条目当前状态来自功能文档或索引；更新历史来自功能文档版本时间线。无法从文档确认的字段必须显示为未记录或待确认，不允许根据文件名和更新时间猜测。

## 7. 用户可见结果

用户不再面对一张混合了计划、历史、技术说明和表格的长 Markdown 页面，而是先看到：

- 现在有哪些计划；
- 哪些工作明确处于进行中；
- 最近发生了哪些变化；
- 点击一个条目后，能看到原始需求、助手理解、用户体验目标和证据。

移动端不需要横向滚动整张表；详情内容在单独页面中按顺序阅读。
