# Codex Collab Panel：产品目标、理想功能、适用场景与竞品优势

文档日期：2026-07-22

评审负责人：Codex

身份与职责：AI 项目负责人，统一协调产品、技术、兼容、质量、安全和市场方向；负责识别意见冲突、维持项目边界，并对尚未验证的能力保持质疑。

本文用途：单独记录本项目经过讨论后对齐的产品方向，不修改或替代原仓库的 `PROJECT.md`、README 和开发日志。

## 一、产品定义

本项目的理想形态不是换肤工具、普通聊天软件或单纯的 Codex 会话浏览器，而是：

> 一个以管理层群聊为入口、以专项 Agent 为执行团队、以项目大脑为长期记忆的 AI 原生项目协作空间。

一个项目对应一个项目群。人类成员可以在群里日常交流、讨论项目、确认优先级和做关键决定；项目负责人 Agent 负责总结、澄清、拆解、协调和汇报；开发、产品、设计、测试、研究、营销等专项 Agent 在后台执行具体工作，并在关键节点向群里汇报。

当前 Codex 右侧面板和网页会话能力，应当被视为 Agent 连接、状态提取与展示原型，是未来产品的数据入口之一，不等于完整产品已经成立。

## 二、核心工作闭环

```text
管理层群聊产生讨论和决定
        ↓
项目负责人 Agent 澄清、整理和拆分
        ↓
专项 Agent 分别执行
        ↓
关键进度、成果、风险和待确认事项回到群里
        ↓
管理层确认或调整方向
        ↓
项目大脑沉淀决策、任务、结果、验证和经验
```

群聊负责沟通，专项 Agent 负责执行，项目负责人 Agent 负责协调，项目大脑负责记忆，管理层保留最终决定权。

项目长期要建立的核心关系是：

```text
聊天消息 → 决策 → 任务 → Agent 执行 → 产物 → 验证 → 项目记忆
```

每个结论应能够追溯到原始消息、文件、提交或 Agent 工作记录。

## 三、理想功能

### 1. 管理层群聊

- 支持日常聊天、项目讨论、回复、引用、文件、话题和 `@Agent`。
- 区分普通闲聊、项目背景、候选需求、明确决定和执行指令。
- 支持把一条消息转成任务、决定或待确认事项。
- 闲聊默认不进入项目记忆，重要信息由 AI 识别并在必要时等待人工确认。

### 2. 项目负责人 Agent

- 总结群聊并维护项目状态。
- 识别需求变化、意见冲突、范围扩大和长期阻塞。
- 将目标拆成任务并推荐合适的专项 Agent。
- 汇总专项 Agent 的进度、成果和风险。
- 生成日报、周报和阶段报告。
- 维护待确认事项，但不擅自替管理层做关键决定。

### 3. 专项 Agent 团队

- 开发 Agent：修改代码、修复问题和提交变更。
- 产品 Agent：梳理需求、流程和验收标准。
- 设计 Agent：制作方案并检查视觉与交互一致性。
- 测试 Agent：复现问题、运行测试并验证结果。
- 研究 Agent：搜索资料、核实事实并对比方案。
- 营销 Agent：准备内容、渠道和发布计划。
- 运维 Agent：检查部署、运行状态和日志。

专项 Agent 不应把全部工具日志发进群，只汇报开始、关键进展、阶段成果、风险、待确认事项和最终验证结果。

### 4. 实时项目状态

持续展示：

- 当前目标和阶段。
- 已确认决定。
- 正在进行和已完成任务。
- 各专项 Agent 的状态。
- 风险、阻塞和待管理层确认事项。
- 负责人、截止时间和最近变化。

状态需要区分来源：管理层已确认、AI 提取待确认、Agent 工作报告、代码或测试等系统证据。

### 5. 项目大脑

吸收 SageOx 类产品的长期记忆优势：

- 保存项目背景、目标和重要决定。
- 记录需求变化、任务结果和验证信息。
- 沉淀成功经验和失败原因。
- 关联群聊、会议、文档、代码和 Agent 会话。
- 支持搜索和来源追溯。
- 为新成员生成项目介绍。
- 为新 Agent 自动提供必要上下文。
- 自动生成每日、每周和阶段记忆。

### 6. 任务、权限与审批

- 群聊指令可以转成目标明确、范围清楚的任务。
- 每个 Agent 有独立职责、工具权限、数据范围和汇报规则。
- 支持暂停、取消、重新执行和人工接管。
- 删除、发布、付费、对外发送、权限变化和需求变更等关键行为必须人工确认。

### 7. 外部连接

成熟后可逐步接入 Codex、Claude Code、Cursor、GitHub、飞书、Slack、Figma、Notion 和会议系统，但第一阶段不同时建设全部连接。

外部信息进入后应转成明确的项目事件，例如 PR 创建、测试失败、设计更新、客户反馈和部署完成，而不是简单复制消息。

## 四、适用场景

### AI 原生研发团队

多个成员同时使用不同编码 Agent，管理层需要了解真实进度、风险和待确认问题，但不希望阅读全部终端和对话日志。

### 创业公司管理层

创始人、产品和技术负责人在群里讨论方向，产品、开发、研究和营销 Agent 在后台执行，项目负责人 Agent 负责协调和汇报。

### AI 内容与短剧团队

用于管理选题、剧本、分镜、图片和视频生成、配音、剪辑、审核和运营，并保存模型、提示词、素材版本和试验经验。

### 营销与电商项目

研究、文案、设计、投放和数据 Agent 分工执行，管理层在群里确认活动方向、素材、预算、发布和优化方案。

### 咨询与研究团队

研究和分析 Agent 搜集资料、形成观点、生成报告并保留来源，评审 Agent 独立检查证据和结论。

### 企业内部专项项目

适合系统迁移、流程改造、安全整改等需要跨部门进度、权限边界和决策追溯的项目。

当前不以纯社交聊天、完全自主决策的 AI 公司或立即替代飞书、Slack、GitHub、Notion 的大型办公平台为目标。

## 五、竞品差异与潜在优势

### 相比 SageOx

SageOx 更偏团队知识、Agent 记忆、会议与工作历史；本项目优先解决实时管理、群聊协调、派工、审批和项目状态。可以概括为：SageOx 帮助团队和 Agent 记住过去，本项目帮助管理层指挥现在，同时沉淀过去。

### 相比飞书和 Slack

Agent 不是普通聊天机器人，而是具有真实任务、执行状态、工具权限、汇报关系和验证记录的专项成员。群聊需要持续生成结构化项目状态，而不是只生成一段摘要。

### 相比 Codex 和 Happy

Codex 和 Happy 主要帮助个人从不同设备管理自己的 Agent；本项目希望让多个成员共同管理一个项目中的多个 Agent，并形成团队共同确认的项目状态。

### 相比 GitHub、Linear 和 Cursor

本项目不局限于代码仓库、Issue 或单一云端 Agent，可以覆盖产品、设计、研究、内容、营销和运营工作，并把技术工作转成管理层可以理解的目标、进度、风险和审批事项。

### 可能形成的壁垒

- 可追溯的“聊天、决策、任务、Agent 执行、产物、验证、记忆”关系。
- 跨不同 Agent 的统一身份、职责、权限和状态模型。
- 原始内容在本地筛选，只共享协作所需的最少信息。
- 将技术执行转换成管理层语言的能力。
- 以群聊作为高频入口，同时保持项目状态和长期记忆连续。

单独的群聊、摘要或 Agent 面板都容易被复制。只有派工、执行、汇报、审批、验证和记忆形成完整闭环，竞争优势才成立。

## 六、第一阶段最小产品

第一阶段只验证：

```text
两名人类成员
+ 一个项目群
+ 一个项目负责人 Agent
+ 一个专项 Agent
+ 一份自动更新、可追溯的项目状态
```

第一阶段需要证明：

- 用户愿意每天打开项目群。
- Agent 的真实工作能够形成准确、克制的汇报。
- 群聊中的决定能够更新项目状态。
- 闲聊不会污染项目记忆。
- 重要操作始终由人类确认。

在这个闭环得到真实用户验证前，不优先扩展完整企业组织、多项目后台、大量内容类型或未经确认的远程控制。
