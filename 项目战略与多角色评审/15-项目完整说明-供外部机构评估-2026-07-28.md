## 一、项目概览

### 1. 项目名称

Codex Collab Panel。

### 2. 项目当前性质

这是一个围绕 OpenAI Codex 工作过程构建的单项目 Web/PWA 协作原型。当前已经能够读取和控制真实 Codex 会话、显示实时执行状态、组织项目群中的多 Agent 讨论，并开始把 Agent 生成的真实文件、网页和 PDF 作为可预览、可审核的项目交付物呈现。

项目并非 OpenAI 官方产品，也不是对 Codex Desktop 的修改版。当前主要通过 Codex `app-server`、本地会话记录和本机 Node.js 服务连接真实任务。

### 3. 项目希望解决的问题

Codex 等 Agent 可以持续执行较长时间，但其工作过程通常分散在个人电脑和个人会话中。团队其他成员可能不知道：

- 当前由谁向 Agent 提出了什么要求；
- Agent 正在执行什么、是否发生阻塞；
- 需求是否已经变化或失效；
- 哪些结果已经确认，哪些仍需人工决定；
- 成员离开电脑后，如何继续查看和控制真实任务；
- 多个成员和多个 Agent 如何围绕同一个项目共享必要上下文。

项目尝试把这些原本只存在于个人 Codex 窗口中的信息，转化为可查看、可讨论、可干预的项目状态。

### 4. 当前阶段

当前不是正式商业产品，而是“真实链路已经跑通、核心体验等待持续验收”的 Demo 阶段。

目前已经完成的核心证明是：

1. 浏览器能够读取一个项目中的真实 Codex Thread 和结构化对话；
2. 用户可以从电脑浏览器或手机向真实 Thread 发送指令；
3. 页面能够通过 SSE 显示执行状态、增量回复和活动信息；
4. 项目群可以调度多个真实 Codex Agent 进行有限轮次讨论；
5. 页面已经具备 PWA、设备名称、附件和移动端入口；
6. 用户可以新建真实 Codex Thread、切换后续 Turn 使用的模型，并查看上下文占用；
7. 手机重新打开时可以先显示受控会话快照，再在后台同步最新内容；
8. Agent 交付物已经具备发布、预览、版本、批准和打回的基础闭环；
9. 明确要求生成网页时，开发 Agent 可以生成静态 HTML，并通过 Edge 转换为 PDF 后双文件交付；
10. Desktop 冷启动读取 Web 对话已经由用户验证，但已经打开的 Desktop 页面仍未实现实时热同步。

## 二、项目的起点与演变

### 1. 原始技术来源

项目最初基于 Codex Dream Skin 的本机 CDP 注入能力进行实验。早期原型在 Codex Desktop 右侧注入“项目实时总结”面板，但不修改官方安装包、`app.asar` 或代码签名。

早期面板读取本地 Codex JSONL 会话，只提取用户消息和助手最终回复，再调用模型生成四段式摘要：

- 当前目标；
- 已确认事项；
- 进行中事项；
- 待确认事项。

这一阶段证明了“真实会话读取 + 项目摘要 + Codex 内嵌面板”的可行性，但 CDP 注入依赖 Codex 页面结构，因此没有被视为长期唯一架构。

### 2. 产品设想的形成

项目最初的用户场景是：Codex 在电脑上长时间工作时，用户可以离开电脑，通过手机查看进度，并与同样使用 Agent 的朋友或同事交流。

随后，设想扩展为团队协作：当其他成员发现需求变化、信息错误或风险时，可以及时提醒任务发起人，避免 Agent 按过期需求继续执行。

再之后，项目形成了三个层次的长期设想：

1. 单人跨设备查看与控制真实 Codex；
2. 多人在项目群中查看、讨论和干预多个 Agent 的工作；
3. 项目经理 Agent 整理目标、决策、进度、风险和待确认事项。

## 三、当前产品形态

### 1. 单人 Codex Web 页面

用户可以在浏览器中：

- 查看当前项目的真实 Codex/Happy 会话；
- 读取真实标题和结构化消息；
- 切换会话并分页加载较早历史；
- 查看 Markdown、代码、表格、选项和媒体内容；
- 向真实 Codex Thread 发送指令；
- 在任务运行过程中追加引导；
- 停止正在进行的任务；
- 查看当前执行阶段、活动、增量回复和错误状态；
- 查看真实模型及上下文占用；
- 手动压缩上下文，或设置自动压缩阈值；
- 新建当前项目的真实 Codex Thread；
- 读取本机可用模型并切换当前 Thread 后续 Turn 使用的模型；
- 手机重新打开时先显示最近会话快照，再后台同步真实数据；
- 查看公开的分析摘要和经过简化的实际命令，而不是空洞状态或冗长 PowerShell 启动路径；
- 在发送超时后确认真实 Turn 是否已经启动，降低重复提交任务的风险。

该页面的目标是让用户离开电脑后，仍能通过手机或浏览器继续一个真实 Codex 任务，而不是建立一个与真实任务无关的聊天演示。

### 2. 项目群聊与多 Agent 页面

当前项目群包含持久化群消息、真实成员和四种 Agent 角色：

- 项目经理 Agent；
- 研究 Agent；
- 开发 Agent；
- 审查 Agent。

用户可以：

- 在项目群中发送真实消息；
- 选择或通过 `@` 点名一个或多个 Agent；
- 在讨论模式或开发模式中启动 Agent；
- 查看 Agent 的当前阶段和增量回复；
- 让 Agent 在有限轮次中邀请其他 Agent 继续讨论；
- 查看群成员、附件和新消息状态。

当前多 Agent 讨论不是无限自主运行。系统限制上下文和讨论轮次，以避免无边界 Token 消耗。正式任务队列、取消、重试、权限和冲突仲裁仍未完成。

### 3. 附件与内容展示

当前支持：

- GitHub Flavored Markdown；
- 标题、列表、引用和链接；
- 代码块和表格；
- 结构化选项；
- 图片；
- 音频；
- 视频；
- 普通文件的打开或下载。

单个附件当前限制为 20 MB，一次最多 6 个。媒体通过服务端登记后的 ID 访问，而不是允许浏览器任意读取电脑绝对路径。

普通 HTML 等高风险内容不会直接插入主页面执行。新增加的网页成果使用短期随机 Ticket 和严格 CSP 沙箱在独立路由打开，不携带项目 Token，也不允许脚本、同源权限、外部网络、表单或对象执行。

### 4. Agent 交付物、版本和审核

项目已经增加独立的 Artifact 功能域。Agent 生成的文件不再只以回复文本中的本机路径出现，而可以登记为结构化交付物并关联到群消息。

当前已实现：

- 交付物发布与元数据持久化；
- 文件名、类型、大小、创建 Agent、版本和审核状态；
- Markdown、图片、音视频和 PDF 预览；
- 所有文件的受控下载；
- 用户批准或填写原因打回；
- 历史版本查看；
- `artifact.ready`、`artifact.reviewed` 等 SSE 更新；
- 读取失败时显示错误并允许重试。

当前尚未完成 Office 文件转换、病毒扫描、对象存储、大文件分片、正式组织权限和自动返工循环。

### 5. HTML 网页与 PDF 双文件交付

当用户在项目群中明确要求制作 HTML、网页或报告页时，当前开发链路可以：

1. 在受控任务目录生成静态、自包含的 `index.html`；
2. 使用本机 Edge 无头模式生成并校验 `result.pdf`；
3. 将 HTML 和 PDF 登记为两个独立 Artifact；
4. 把两份交付物关联到同一条开发 Agent 最终消息；
5. 允许用户打开、下载、批准或打回成果。

当前代码和定向测试已经提交，但尚未完成用户端真实 Edge 冒烟与完整体验验收。该能力不是通用网站托管、在线编辑器或无限 Agent 自动返工系统。

### 6. PWA、手机和平板入口

Web Demo 已加入：

- PWA Manifest；
- Service Worker；
- 手机和 Apple Touch 图标；
- 添加到手机或 iPad 主屏幕的入口；
- 当前连接电脑的设备名称；
- 在线和重连状态；
- 单人对话与项目群聊切换；
- 手机窄屏布局；
- iPad 双栏布局。

首次访问仍使用访问令牌。验证后，服务端可以写入 HttpOnly Cookie，使已经安装的 PWA 不需要依赖启动 URL 长期保存查询参数。

项目已经验证临时 HTTPS Tunnel 入口，且尝试配置了固定子域名和 Windows cloudflared 服务；但固定入口研究目前按用户要求延期，Cloudflare Access、项目服务开机恢复、正式账号、设备绑定、权限撤销和系统推送仍未完成。当前远程访问仍属于 Demo 级能力，本文不公开具体地址和访问令牌。

### 7. 早期右侧总结面板

早期 Codex Desktop 右侧面板仍是项目演进中的重要原型，已经验证：

- 本地会话连接状态显示；
- 最近一次用户要求和助手回复预览；
- 四段式项目摘要；
- 摘要模型、耗时、更新时间和错误状态；
- 面板关闭与重新打开。

当前主要开发重心已经转向 `web-ui/` 和 `windows/server/`，右侧面板不再代表项目全部能力。

## 四、当前用户流程

### 1. 单人跨设备流程

```text
电脑上的 Codex 产生真实 Thread
        ↓
本地服务通过 app-server 或 JSONL 读取任务
        ↓
用户在手机或浏览器查看真实会话
        ↓
用户发送新指令、追加引导或停止任务
        ↓
Codex app-server 执行
        ↓
状态和增量回复通过 SSE 返回页面
```

### 2. 多 Agent 群聊流程

```text
用户在项目群发送消息
        ↓
默认交给项目经理 Agent，或通过 @ 指定 Agent
        ↓
系统加入完成当前讨论所需的群聊上下文
        ↓
一个或多个 Codex Agent 按有限轮次执行
        ↓
群页面展示 Agent 状态、增量内容和最终消息
```

### 3. 当前跨端限制

Web 使用独立 Codex app-server 进程。即使 Web 和 Codex Desktop 引用同一个持久化 Thread，也不代表它们共享同一个实时运行实例、事件订阅或 UI 状态。

因此：

- Web 新增的消息可以写入真实 Thread；
- Web 可以实时显示自己连接的 app-server 事件；
- 已经打开的 Codex Desktop 页面不会自动热刷新 Web 新增内容；
- 当前不建议 Desktop 和 Web 同时向同一个 Thread 并发发送；
- 用户已经验证 Desktop 完全关闭后重新打开任务，可以读取 Web 产生的对话；
- 冷启动可恢复持久化内容不等于已实现实时事件共享、控制权交接或并发仲裁。

## 五、技术架构

### 1. 技术栈

前端：

- React 19；
- TypeScript；
- Vite；
- `@tanstack/react-virtual`；
- `react-markdown` 与 `remark-gfm`；
- PWA Manifest 与 Service Worker。

后端：

- Node.js 原生 HTTP 服务；
- Codex `app-server` 协议；
- SSE 实时事件；
- 本地 JSONL 会话读取作为历史来源和降级路径；
- PowerShell 启动、构建和安装脚本。

包管理器：`pnpm@10.28.2`。

### 2. 单人会话数据链路

```text
Codex app-server
  thread/list + thread/read + thread.name
                ↓
app-server-conversation-store
                ↓ 失败时回退
JSONL conversation store
                ↓
conversation-service
                ↓
content-blocks + media-service
                ↓
HTTP API + SSE
                ↓
React Web UI
```

### 3. 执行链路

浏览器向后端发送指令后，系统根据任务状态使用：

- `turn/start`：没有活动 Turn 时开始任务；
- `turn/steer`：任务运行过程中追加引导；
- 停止接口：终止当前任务；
- `thread/compact/start`：启动上下文压缩；
- `thread/start`：创建真实新对话；
- `model/list`：读取本机可用模型；
- `thread/settings/update`：切换当前 Thread 后续 Turn 使用的模型。

Codex app-server 的通知由执行跟踪器转换为用户可见状态，再通过 SSE 分发给页面。

### 4. 主要后端模块

| 模块 | 作用 |
| --- | --- |
| `app-server-client.mjs` | 启动并通过 stdio 调用 Codex app-server |
| `app-server-conversation-store.mjs` | 把 Thread 数据转换为统一会话模型 |
| `jsonl-conversation-store.mjs` | 读取本地 JSONL，作为历史与降级数据源 |
| `conversation-service.mjs` | 选择主要数据源和回退路径 |
| `execution-tracker.mjs` | 转换 Turn、Item、Delta 和错误事件 |
| `context-management-service.mjs` | 读取模型、上下文占用并管理压缩 |
| `content-blocks.mjs` | 标准化文本、代码、媒体等内容块 |
| `media-service.mjs` | 登记和受控读取附件及媒体 |
| `artifact-service.mjs` | 登记 Agent 交付物、版本、审核状态和文件关系 |
| `web-output-service.mjs` | 管理静态 HTML 输出、安全预览和 Edge 转 PDF |
| `group-room-store.mjs` | 保存群、成员和群消息 |
| `multi-agent-service.mjs` | 调度目标 Agent、上下文和有限轮次讨论 |
| `realtime-hub.mjs` | 管理 SSE 客户端和刷新通知 |
| `request-handler.mjs` | 处理会话、群聊、设备、媒体和静态页面请求 |

### 5. 数据与状态边界

项目当前明确区分以下对象：

- 持久化 Thread；
- app-server 实时连接；
- Codex Desktop 当前 UI 状态；
- 单人 Turn 的执行状态；
- 群聊中的 Agent 队列状态；
- 项目群消息；
- 附件登记与媒体访问权限；
- Agent 交付物、版本和审核状态；
- HTML/PDF 输出任务及其受控预览 Ticket。

这些对象可能共享部分信息，但不能简单视为同一套状态。

以下内容已有代码、测试记录或真实运行记录支持：

- 可以读取真实 Codex Thread、真实标题和结构化消息；
- app-server 读取失败时存在 JSONL 回退路径；
- 浏览器可以向真实 Codex Thread 发送指令；
- 可以接收执行状态和流式回复；
- 运行过程中可以追加引导和停止；
- 长对话支持分页、缓存和虚拟列表；
- 内容支持 Markdown、代码、表格和多种媒体；
- 项目群可以调度多个真实 Codex Agent；
- 上下文占用和压缩使用 Codex app-server 的真实能力，不按消息数量猜测；
- 可以创建真实新 Thread，并通过本机 app-server 协议读取和切换模型；
- 手机尺寸定向检查中，会话快照约 264 毫秒出现，后台同步完成后提示自动消失；
- 用户已经验证 Desktop 冷启动后可以读取 Web 产生的对话；
- Agent 交付物的发布、版本、审核、错误重试及 SSE 事件已有代码和定向测试；
- HTML 安全预览、Edge 转 PDF 和双文件发布已有代码和 4 项服务端定向测试；
- 临时 HTTPS Tunnel 的项目 API 和 SSE 已有连通记录；
- Windows 原有安全测试套件当前通过；
- 最新开发记录显示 React/TypeScript/Vite 生产构建及多项定向测试通过。

## 八、尚未证明或尚未完成的事项

### 3. 多人和多 Agent

## 九、安全、隐私与合规边界

项目现有记录确认的原则包括：

1. 本地原始对话默认不应无条件离开电脑；
2. 不展示或同步模型内部推理过程；
3. 不把 API Key 写入页面或项目文件；
4. 不通过修改 JSONL 伪造跨端同步；
5. 浏览器不能提交任意电脑绝对路径来读取文件；
6. 媒体先由服务端登记，再通过受控 ID 访问；
7. HTML 等高风险内容不直接执行；
8. 远程控制和高影响操作应具有明确授权与人工确认；
9. 正式公网使用前必须补充 HTTPS、正式鉴权、权限和撤销机制；
10. 当前 Demo Token 不能被视为正式账号系统。

对于新增加的 HTML 成果，当前设计使用短期随机 Ticket、`no-store`、严格 CSP 和沙箱限制，避免生成页面获得主站 Cookie、Token、同源权限或外部网络能力。该实现仍需要真实部署环境中的安全复核。

当前仍需要进一步设计的安全能力包括：

- 用户、设备和项目身份；
- 访问令牌生命周期与撤销；
- 成员级和操作级权限；
- 审批、审计和事件追踪；
- 敏感字段过滤；
- Agent 可访问工具和文件的范围；
- 多租户隔离；
- 公网暴露和本地网络边界；
- 附件病毒扫描及内容安全。

## 十一、项目当前存在的结构性矛盾

以下是项目自身文档已经记录、但尚未完全解决的矛盾：

### 1. 项目身份

默认 README 仍以 Codex Dream Skin 换肤工具为主要内容，而当前开发目标已经转向 Codex Collab Panel。外部读者可能无法立即判断仓库究竟是主题工具、远程控制工具、Agent 群聊，还是团队协作平台。

### 2. 当前产品与长期愿景

当前真实能力已经从单项目 Web 控制和多 Agent 群聊扩展到模型控制、远程入口、交付物审核和 HTML/PDF 生成；长期设想还包含公司全流程、项目经理 Agent、多人权限、跨设备和多个执行节点。能力扩展速度较快，但哪些功能构成主产品仍缺少经过用户和付费场景验证的结论。

### 3. 单人任务与群聊状态

单人 Codex Turn 和群聊 Agent 队列看起来相似，但属于不同状态模型。强行合并会造成执行状态、取消、重试和控制权混乱。

### 4. 相同 Thread 与实时同步

相同 Thread 只代表持久化任务可能相同，不代表不同客户端共享同一个运行实例和事件流。这是当前跨端体验最主要的技术边界。

### 5. 本地优先与远程协作

项目希望敏感数据默认留在本地，同时又希望实现手机、网页和多人远程协作。需要进一步明确哪些数据可以上传、如何筛选、如何加密，以及由谁授权。

### 6. 功能增长与产品收束

最新分支已经同时包含单人控制、群聊、多 Agent、PWA、公网入口、Artifact、审核和网页/PDF生成。技术闭环更加完整，但外部机构仍需要判断这些能力是一条统一工作流，还是多个尚未收束的产品方向。

## 十二、长期方向记录

以下内容属于项目已经讨论和记录的长期方向，不代表已经立项或验证。

### 1. 项目经理 Agent

持续整理不同成员和 Agent 的：

- 目标；
- 决策；
- 任务；
- 进度；
- 风险；
- 待确认事项。

其定位首先是信息整理者和风险提醒者，而不是未经授权替团队做决定。

### 2. 多项目与组织协作

不同项目或工作主题拥有独立群组、成员、Agent、数据和权限。团队可以看到谁正在指挥哪个 Agent，以及项目最近发生了什么。

### 3. AI 内容公司场景

项目设想也适用于 AI 视频、AI 短剧和内容生产团队，用于管理：

- 脚本和分镜；
- 素材及角色一致性；
- 提示词、模型和参数；
- 生成结果和失败原因；
- 修改意见和版本；
- 编剧、导演、剪辑、运营和 Agent 的共享上下文。

### 4. “平行世界”方向

项目战略文档提出过一种更远期的差异化方向：将一个重要选择分叉为多个隔离、可执行的项目版本，由不同 Agent 团队分别完成，然后比较代码、页面、测试、成本、风险和进度，再由人选择或合并结果。

该方向目前主要是产品战略设想，尚未形成独立产品闭环或用户验证。

### 5. 本地执行节点与云端协作层

另一个长期架构设想是：代码、终端和敏感工具继续运行在用户电脑或自有服务器；云端只负责项目消息、经过筛选的状态、权限、加密同步和移动端连接。

该架构尚未定案。

## 十四、当前建议的演示内容说明

如果外部机构希望先了解现有能力，可按以下顺序查看 Demo：

1. 在 Web 页面读取一个真实 Codex Thread；
2. 从浏览器发送一个真实任务；
3. 查看执行状态、增量回复和最终结果；
4. 运行中追加引导或停止；
5. 查看模型、上下文占用和压缩；
6. 新建一个真实 Thread，并展示模型列表与切换；
7. 在手机重新打开页面，展示快照先出现、后台再同步；
8. 从单人页面切换到项目群；
9. 在项目群中 `@` 项目经理、研究、开发或审查 Agent；
10. 查看多个 Agent 的有限轮次讨论；
11. 展示一个已登记交付物的预览、下载、版本、批准和打回；
12. 明确要求开发 Agent 生成静态网页，展示 HTML 与 PDF 双文件结果；
13. 在手机或 PWA 入口查看设备名称和在线状态；
14. 说明 Desktop 冷启动可以读取 Web 对话，但已打开页面仍不会热同步，避免把尚未完成的能力当作已实现功能。

## 十五、总结

Codex Collab Panel 已经从一个 Codex Desktop 右侧总结面板，发展为包含真实会话读取、浏览器任务控制、实时恢复、多 Agent 项目群、附件、PWA、模型与上下文管理、Agent交付物审核及HTML/PDF输出的单项目协作 Demo。

项目目前最扎实的技术成果，是跑通了“真实 Codex 数据—本地服务—Web/手机页面—真实执行—结构化交付物”的闭环，并开始验证多人和多 Agent 在同一项目空间中讨论、执行、交付和审核的交互形式。

项目尚未完成的核心工作，不只是继续增加功能，而是明确单人远程控制、团队 Agent 协作和交付物工作流之间的主次关系，同时解决 Desktop/Web 连续性、服务半失效恢复、正式身份权限、安全部署、用户验收和商业数据等问题。

当前需要外部机构帮助判断的重点，是哪些已有能力能够组合成一个清晰、独立、可付费的产品，以及在什么证据出现后，这个项目才具备进一步融资和规模化投入的条件。
