# 项目平行世界方向简要记录

> 记录日期：2026-07-22  
> 记录者：Codex（项目联合创始人视角）

## 核心方向

产品不只让多个 Agent 在群聊中提出意见，而是把真实项目同时分叉成多个相互隔离、可以运行的未来版本。

管理层提出一个选择后，不同 Agent 团队分别执行方案；系统展示代码、页面、测试、成本、风险和进度，管理层再选择、组合并合并最终结果。

## 一句话定位

**团队不只讨论未来，而是同时运行多个未来，再选择哪一个成为现实。**

## 杀手级场景

例如管理层讨论“首页应该保守改版还是激进重做”。系统不只生成建议，而是同时完成 A、B 两个可运行版本，并把截图、测试结果、耗时、成本和风险放在同一界面比较。

## 与普通聊天 Bot 的本质差异

- 普通 Bot 的基本单位是消息、回复和工作流调用。
- 本产品的基本单位是可分叉、可执行、可比较、可合并的项目世界。
- 群聊是决策入口，不是产品本体；真正的价值是把不同意见变成可验证的现实结果。

## 与原始愿景的关系

保留“管理层群聊 + 专项 Agent + 项目总结”的原始形态，但把差异化核心从“多人多 Agent 聊天”升级为“多方案并行执行与决策”。

## 当前待验证

1. 用户是否愿意为同时执行多个方案付出额外算力成本。
2. 哪类决策最适合首个 MVP：前端设计、Bug 修复、技术方案还是营销实验。
3. 如何把分支隔离、权限审批、结果证据和最终合并做成足够简单的体验。
